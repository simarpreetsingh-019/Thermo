Your Mac's heat, load and battery,
right beside the notch.

Thermo is a free, open-source macOS app that shows live CPU, GPU, memory and temperatures, tells you what's slowing your Mac and what to close, and lets your apps and AI agents ask "is there room for this heavy job?"

Install free Connect an AI agent ★ Star on GitHub

What it does

About 16 MB of memory and 2–3% of one CPU core. No admin rights, no kernel extensions, no telemetry.

Notch HUD

Glowing gauges beside the notch. Hover to expand, drag down to float. Menu-bar mode for Macs without a notch.

Every temperature

CPU performance and efficiency cores, GPU, memory, SSD, battery, Wi-Fi and palm rest, each with its own safe range.

Heat advisor

What's causing the heat, what slows down, how long to cool, and one-click quit.

Memory advisor

Real memory pressure and swap, not just "% used". No fake RAM cleaning.

Battery health

Health %, condition, cycles, watts in or out, time left, and a daily health log.

History

CPU, memory, GPU and temperature graphs for the last hour or 24 hours.

Smart alerts

A small card when your Mac stays hot, memory stays tight, or an app gets stuck.

For agents and apps

CLI with JSON, an MCP server, a local API, and Python, JavaScript and Swift helpers.

Install

macOS 13 or later. Apple Silicon and Intel.

Homebrew (recommended)

brew install --cask simarpreetsingh-019/thermo/thermo

This also adds the thermo command.

No Homebrew: installer script

It downloads the latest release and checks the SHA-256 checksum, GitHub attestation (if you have gh) and code signature before installing. If any check fails, nothing is installed. Read it first, it's short.

curl -fsSL https://raw.githubusercontent.com/simarpreetsingh-019/Thermo/main/install.sh -o install.sh
bash install.sh

Direct download

Get Thermo.zip from Releases, unzip, and drag Thermo into Applications.

Why macOS warns you: Thermo is free and open source but not yet notarized by Apple (that needs a paid developer account), so macOS says it can't verify it. That means "Apple hasn't checked this", not "this is harmful". To open it once: double-click Thermo, click Done, then go to System Settings → Privacy & Security and click Open Anyway. On macOS 14 and earlier, right-click → Open works too.

Check your download yourself

shasum -a 256 ~/Downloads/Thermo.zip                 # compare with the release notes
gh attestation verify ~/Downloads/Thermo.zip --repo simarpreetsingh-019/Thermo

Use it by hand

The app is the main way to use Thermo. The thermo command gives the same readings in Terminal. Add --json to any reading for machine-readable output.

CommandWhat you get
thermo statusCPU, GPU, memory, heat, battery and a one-line health summary
thermo tempsTemperature of each part
thermo apps --sort memoryBusiest apps by CPU or memory
thermo batteryHealth, cycles, charge, watts, time left
thermo history --range 24hAverages and peaks for 1 or 24 hours
thermo headroom --kind gpu --memory-gb 8Room for a heavy job? Exit code 0 go, 3 wait, 4 no
thermo wait-cool --target 70Waits until the Mac cools, then returns
thermo open | quit | restart | update | versionControl the app

Homebrew adds the thermo command automatically. Installed from the zip? Use ⚙ → Connections → Install thermo command in Terminal (asks for your password once), or say yes when the installer script offers it. You can also call the app directly: /Applications/Thermo.app/Contents/MacOS/Thermo --cli status.

Gate your own scripts

thermo headroom --kind gpu --memory-gb 12 || thermo wait-cool --target 70
python train.py

Connect an AI agent

Thermo includes an MCP server, so any MCP-compatible agent can check your Mac before heavy work. It's the app itself, no extra install: /Applications/Thermo.app/Contents/MacOS/Thermo --mcp.

Plugin with the MCP server and a skill that tells Claude when to check headroom:

/plugin marketplace add simarpreetsingh-019/Thermo
/plugin install thermo@thermo

Or the MCP server only:

claude mcp add thermo -- /Applications/Thermo.app/Contents/MacOS/Thermo --mcp

Settings → Developer → Edit Config, then add:

{ "mcpServers": { "thermo": { "command": "/Applications/Thermo.app/Contents/MacOS/Thermo", "args": ["--mcp"] } } }
codex mcp add thermo -- /Applications/Thermo.app/Contents/MacOS/Thermo --mcp

Optional: add the AGENTS.md snippet, or copy the skill to ~/.codex/skills/thermo/.

Add to ~/.cursor/mcp.json:

{ "mcpServers": { "thermo": { "command": "/Applications/Thermo.app/Contents/MacOS/Thermo", "args": ["--mcp"] } } }

Optional rule: thermo.mdc → .cursor/rules/.

.vscode/mcp.json:

{ "servers": { "thermo": { "command": "/Applications/Thermo.app/Contents/MacOS/Thermo", "args": ["--mcp"] } } }

Windsurf, Zed, Cline and any other MCP client: command /Applications/Thermo.app/Contents/MacOS/Thermo, arguments ["--mcp"], transport stdio.

Use it from your own app

Copy one file: Python, JavaScript or Swift. Each uses the local API when it's on and the command line otherwise.

from thermo_client import Thermo
t = Thermo()
h = t.headroom(kind="gpu", memory_gb=8)
if h["verdict"] != "go":
    print(h["advice"]); t.wait_until_cool(target=70)

Local HTTP API

Off by default. Turn it on in Thermo: ⚙ → Connections → Local API for other apps. It listens only on 127.0.0.1:47615, is read-only, and every data request needs the token stored in ~/Library/Application Support/Thermo/api.json (readable only by you).

TOKEN=$(python3 -c "import json,os;print(json.load(open(os.path.expanduser('~/Library/Application Support/Thermo/api.json')))['token'])")
curl -H "Authorization: Bearer $TOKEN" "http://127.0.0.1:47615/v1/headroom?kind=gpu&memory_gb=8"
EndpointSame as
GET /v1/statusthermo status --json
GET /v1/temperaturesthermo temps --json
GET /v1/processes?limit=8&sort=cpu|memorythermo apps --json
GET /v1/batterythermo battery --json
GET /v1/history?range=1h|24hthermo history --json
GET /v1/headroom?kind=gpu&memory_gb=8thermo headroom --json

GitHub Actions

Report a macOS runner's load and temperatures in the job summary, and gate heavy steps.

- uses: simarpreetsingh-019/Thermo@v1
  id: thermo
  with:
    kind: gpu          # any | gpu | cpu | memory
    memory-gb: 6
    fail-on: never     # never | wait | no
    wait-cool: ""      # e.g. 70 to wait until the runner cools
- run: echo "Verdict: ${{ steps.thermo.outputs.verdict }}"

Best on self-hosted Mac runners; hosted runners are virtual machines and may not expose every sensor.

Security and privacy

  • No telemetry and no admin rights. The only network request is a daily update check against GitHub Releases.
  • Updates must match the published SHA-256, pass codesign --verify and carry Thermo's bundle ID.
  • The CLI and MCP server open no network ports. The local API is opt-in, bound to 127.0.0.1, token-protected, read-only, and refuses requests from web pages.
  • App names and project folders are shared with other tools only if you allow it (⚙ → Connections → Share app names).
  • Apps are only quit when you click, and system processes are never offered.
